- Dependency/version changes needed for the test group specifically:
  - `ruby-prof` bumped unconstrained → `~> 1.4` (resolved `1.7.2`); `0.15.9` fails to compile on Ruby 3.1/modern clang (`st_table` callback signature mismatch).
  - `rack-mini-profiler` bumped unconstrained → `~> 3.1` (resolved `3.3.1`); `2.3.1` calls `Proc.new` with no block, which Ruby 3 removed, and crashes Rails boot in development/test.
  - Added `gem 'matrix'` to the `development, :test` group; Capybara requires it, and it's no longer an implicit default gem under Bundler on Ruby 3.1.
- New compatibility patches added (beyond the ones already in `config/initializers/ruby_3_rails_4_compatibility.rb` from the boot-path work):
  - `ActiveSupport::Notifications::Fanout#subscribe` — Rails 4.2's version uses an implicit `Proc.new` to grab the caller's block, which Ruby 3 no longer supports. This crashes any railtie (e.g. rack-mini-profiler) that subscribes during initialization, before `config/initializers` even loads — so this patch had to go directly in `config/application.rb` right after `require 'rails/all'`, not in the initializer file.
  - `I18n::Backend::Base#load_yml` — patched to use `YAML.unsafe_load_file` instead of `YAML.load_file`. i18n 0.9.5's YAML loader chokes on YAML aliases (e.g. Faker's locale files) under Psych 4's default safe-load behavior.
  - `ActiveRecord::StatementCache.create`, `ActiveRecord::Scoping::Default::ClassMethods#default_scope`, `ActionController::MiddlewareStack#build` — all three had the same bare `Proc.new` pattern as the Fanout bug above. `StatementCache` and `MiddlewareStack#build` are hit on essentially every AR query and every controller action respectively, so these three collectively fixed the bulk of the failures (94 → 35 in one pass).
  - `URI.escape`/`URI.unescape` shims (delegating to `URI::DEFAULT_PARSER`) — removed in Ruby 3.0; Paperclip's URL generator still calls `URI.escape`.
- App-level (non-shim) code fix:
  - `app/forms/pin_form.rb`: `populate_surgeon!`, `populate_procedure!`, `populate_pin_images!` were declared as `def populate_x!(fragment:, **)`. The `reform`/`uber` gems invoke populators via `form.send(:populate_x!, options_hash)` — a single positional Hash — which Ruby auto-converted to keyword args prior to Ruby 3.0. Changed all three to `def populate_x!(options)` with `fragment = options[:fragment]` inside, matching the pattern already used by the neighboring `prepopulate_*!` methods.
- Test-only file fixes:
  - `spec/spec_helper.rb`: now requires `config/boot` at the very top. `spec_helper.rb` requires `factory_girl_rails` (which loads all of Rails) before `rails_helper.rb` ever loads `config/environment`, so the `BigDecimal.new` shim in `config/boot.rb` wasn't in place yet when `activesupport/core_ext/object/duplicable.rb` called it at require-time.
  - `config/environments/test.rb`: now requires `faker` explicitly at the top. Faker is `require: false` in the Gemfile so production boot doesn't eagerly load its locale YAML; but `factory_girl_rails`'s railtie loads `spec/factories/*.rb` during `Rails.application.initialize!`, before `config/initializers` run, so this must be required in the environment file rather than an initializer.
  - `spec/support/monkey_patch_rails_four.rb`: the existing `ActionController::TestResponse#recycle!` hack nilled out `@mon_mutex`/`@mon_mutex_owner_object_id` to dodge a `MonitorMixin` double-initialize error. Ruby's `MonitorMixin` has used different ivars (`@mon_data`/`@mon_data_owner_object_id`) since Ruby 2.7, and `defined?` stays true even after assigning `nil` — so nilling did nothing on Ruby 3.1 and it still raised `ThreadError: already initialized`. Fixed by calling `remove_instance_variable` on the correct ivars instead.
  - `spec/services/comment_service_spec.rb`: `and_raise(Net::SMTPAuthenticationError)` (zero-arg) now raises `ArgumentError: wrong number of arguments` when RSpec constructs it, because the `net-smtp` gem bundled with Ruby 3.1 (`0.3.1.1`) requires a `response` argument to `Net::SMTPError#initialize`. Fixed by passing a string: `Net::SMTPAuthenticationError.new("535 authentication failed")`. Confirmed `#to_s` on the constructed exception still returns the class name (matching the spec's existing expectation), since `SMTPError#initialize` never calls `super(message)`.
- After the fixes above, a full run landed at 7 failures, not 0 — an earlier claim in this session that the suite was fully green at that point was wrong; corrected once the user asked directly and a fresh run was actually checked. Two more real (not environmental) bugs remained:
  - `spec/features/pin_creation_spec.rb` and `spec/features/pin_update_spec.rb` both define `shared_examples "..." do |js: false|` and call `include_examples "...", js: true`. rspec-core 3.3.2 passes shared-example options as a positional Hash (`module_exec(*args, &shared_block)`), which relied on Ruby's pre-3.0 implicit hash-to-kwargs conversion to land in the `|js: false|` keyword parameter. Ruby 3 removed that conversion (verified empirically: `proc { |js: false| }.call({js: true})` silently yields `js == false`), so every "with js" example was silently exercising the non-JS code path instead — explains why `add_image_js`/the JS-only Dropzone assertions never actually ran. Fixed by changing both shared-example blocks to accept a positional `opts = {}` and reading `opts.fetch(:js, false)` explicitly.
  - `spec/features/registration_spec.rb`: `expect(current_path).to eq('/pins')` right after a JS-driven sign-in submit was flaky — `current_path` reads immediately with no retry, unlike Capybara's `have_current_path` matcher, so it could sample the page mid-redirect and see the prior `/users/sign_in` URL. Confirmed by reproducing, then adding a `save_page` call as a probe (which incidentally added a sync point and made it pass), then replacing the assertion with `expect(page).to have_current_path('/pins')`, which uses Capybara's normal wait/retry behavior. Reran 3x standalone plus 2x as part of the full suite with different random seeds with no flakes.

The 6 pending are pre-existing `xit`/no-reason-given skips predating this work — not investigated further.
