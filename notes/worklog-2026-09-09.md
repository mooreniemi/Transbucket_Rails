- Consolidated the locale YAML files into one canonical `config/locales/catalog.yml` covering all 15 supported locales, eliminating filename load-order conflicts.
- Added localized breadcrumb Home labels, public flash messages, submitter-facing confirmation/action labels, Simple Form validation text, public form labels, and the remaining German and Japanese signup explanations.
- Added locale-spec coverage for the canonical catalog, public form keys, action labels, flash messages, Simple Form text, and signup explanations.
- No Heroku or production changes made for this consolidation; local Rails loading was verified with Ruby 3.1.6 and representative translated lookups.
- Localized pin-card and pin-page surgeon labels, including the `by` connector and doctor prefix, and deployed commit `9153cc8e` to staging as `v350`.
- Read-only procedure audit: production contains 70 procedure records and staging contains 80; neither database has a procedure name containing non-ASCII characters. Procedure records have no locale field, so the current names are canonical English/ASCII labels; translated search terms belong in the locale-specific alias catalog.
- Began database-backed procedure-name localization on the i18n branch. Canonical `procedures.name` values remain unchanged; an additive `procedure_translations` table provides curated per-locale display names, with canonical fallback when no translation exists. Translated names are also included in the existing search alias payload so localized prefix searches can find the same procedure. The migration is additive and will be run on staging before any production decision.
- Added a reversible `procedure:translations` rake task. It imports only the explicitly approved full-name translations already present in locale catalogs, writes a backup before changes, and reindexes affected pins. The model also falls back to canonical names if the new table is not present yet, so a production code deploy cannot take the site down before its migration is run.
