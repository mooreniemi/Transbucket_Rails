# Worklog 2026-10-04

## Security audit after the Rails 8.1 upgrade

- Scanned the `rails-8-1-upgrade` branch at `e656e708` (Rails 8.1.4, Ruby 3.3.12, Devise 5.0.4, Scout 6.3.1). Rails 8.1 receives security fixes until 2027-10-10, and Ruby 3.3 until about March 2027, so the framework is covered. The remaining exposure is in pinned gems, old front-end libraries, and defaults that were never switched on.
- Tools were installed into a scratch gem home so the project bundle was not changed: `bundler-audit` 0.9.3 with the ruby-advisory-db updated 2026-10-02, and `brakeman` 8.1.0. The bundled `brakeman` 5.0.0 dates from 2021 and should be bumped before relying on it for Rails 8.

### bundle-audit: 16 advisories in 4 gems

- `nokogiri` 1.18.10 (production, used by the HTML sanitizer): 12 advisories. One is High: a ReDoS in the CSS selector tokenizer (CVE-2026-79770, fixed in 1.19.3). One is Medium (CVE-2026-79771, XSLT memory leak). The rest are use-after-free and out-of-bounds reads fixed in 1.19.4. The Gemfile pins 1.18.10 with the comment "Nokogiri 1.19 requires Ruby 3.2"; Ruby is now 3.3.12, so the pin can move to `>= 1.19.4`.
- `cgi` 0.3.6 (production): CVE-2025-27219, a DoS in `CGI::Cookie.parse`, and CVE-2025-27220, a ReDoS in `CGI::Util#escapeElement`. Both are Medium and fixed in 0.3.7 and 0.4.2+. The pin only existed for Ruby 3.1 with Bundler 1.17, so it is now obsolete.
- `rubyzip` 2.4.1: path traversal, High (CVE-2026-85396). `selenium-webdriver` 4.8.1: High (CVE-2023-5590). Both are test-only (rubyzip comes in through selenium), so production is not exposed, but bumping selenium clears both.

### brakeman: 7 warnings, 2 real

- Real, Medium: `config/initializers/cookies_serializer.rb` still uses `:hybrid`, which can Marshal-load old cookies and becomes remote code execution if `SECRET_KEY_BASE` ever leaks. Hybrid has been rewriting cookies as JSON on every write, so switching to `:json` should be safe; confirm on staging that existing sessions survive.
- Real, Low: the contact form's email check (`app/models/message.rb`, `/.+@.+\..+/`) has no `\A`/`\z` anchors. It only affects the contact form.
- False positive: the surgeon `website_url` `link_to`. `Surgeon#website_url` only allows http/https with a host, so a `javascript:` URL cannot get through.
- False positive: the SQL in `deduplicated_pins`. `scope_column` is always the literal `:surgeon_id` or `:procedure_id`.
- False positive, cheap to harden: `RecalculateAvgsQuery` interpolates `type` and `id`, but only from `self.class` and `self.id` in `Stats`. Rewriting it as `Pin.where("#{column}" => id)` would silence the warning.
- Benign: the HEAD/GET verb confusion in `redirect_legacy_locale`. HEAD requests simply skip the locale redirect.

### Other security gaps

- No brute-force protection on login: Devise `:lockable` is off and `Rack::Attack` is commented out. Rails 8's built-in controller `rate_limit` can cover sessions and password resets without a new gem.
- Old front-end libraries from Bower are served to browsers: jQuery 2.1.3 (2014, known XSS advisories), TinyMCE 4.2.6 (2015, known XSS advisories) and Dropzone 4.0.1. Stored content is still rendered safely: `simple_format` sanitizes pin details and comment bodies are escaped.
- Rails security defaults were never adopted: there is no `load_defaults`, so cookies use the legacy encryption and key derivation, per-form CSRF tokens and the Origin check are off, and no Content Security Policy is configured. Use `bin/rails app:update` and `new_framework_defaults_*.rb` to enable them one at a time. The cookie-encryption switch needs a cookie rotator so existing sessions survive.

### Suggested order

1. Bump `nokogiri` to >= 1.19.4 and `cgi` to >= 0.4.2. Both pins are obsolete now that Ruby is 3.3.
2. Add Rails 8 `rate_limit` to login and password reset, and remove `letsrate`.
3. Switch the cookie serializer to `:json` and anchor the contact email regex.
4. Bump the test-only gems (`selenium-webdriver`, `brakeman`) so scans and CI stay current.
5. Adopt the new framework defaults (with a CSP), and replace the Bower libraries, TinyMCE first.
6. Re-run `bundle-audit` and `brakeman` after each step. GitHub Dependabot alerts would automate this on GitHub, which already hosts the code, if the user wants it.

### Dependency fixes after the Rails 8.1 production deploy

- Production reached Rails 8.1.4, but Dependabot still had 14 open alerts because the Gemfile pinned the affected gems: nokogiri (11, including High alert 114), cgi (2 medium, alerts 146 and 147) and rubyzip (High alert 134).
- `nokogiri` is now `~> 1.19, >= 1.19.4` (resolves to 1.19.4).
- Removed the `cgi` pin, so the app uses Ruby 3.3.12's bundled default gem, cgi 0.4.2, which already contains both fixes. `cgi` no longer appears in `Gemfile.lock`.
- `selenium-webdriver` is now `~> 4.50`; 4.8.1 capped rubyzip below 3.0. Added a `rubyzip >= 3.4.0` floor, which resolves to 3.7.0. Both are test-only.
- Verification: `bundle-audit` reports "No vulnerabilities found"; the full suite passes (477 examples, 0 failures, browser specs on Selenium 4.50); and a production-mode boot with Scout and New Relic enabled loads nokogiri 1.19.4 and cgi 0.4.2, with `simple_format` and `sanitize` still stripping script tags, `javascript:` hrefs and event handlers.
